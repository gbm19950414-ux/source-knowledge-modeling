# 独立语义核对指引 · instructional-source@3.0.0

先阅读冻结原件、范围和两张来源清单，再阅读 `checked-drafts.json` 的候选模型。逐项寻找遗漏、擅增、否定丢失、语气下传、数量范围错置、无依据连接、指代遗漏、作者主张与项目解释混淆。不要根据候选图倒写来源期望。

在 `semantic-assessment.json` 写入真实检查者、类型（`AI` 或 `human`）、可取得的模型标识（未知写 `unknown`）、实际检查方式和时间。将 `draft_sha256`、`inventory_sha256`、`discourse_sha256` 绑定到已检查的确切文件。对候选的每项信息、论述、要素和关系分别填写 `{target_kind,target_id,verdict,reason}`；要素与关系另填 `content_revision`。没有检查就不能给 `pass`。

PDF 的来源核验与语义核对均需检查原页，审阅通过不改变作者／项目解释身份。只有评测报告明确通过且来源核验独立完成，才能逐提案记录接受决定。脚本只核对引用、依赖和记录一致性；原文意义是否被准确表达仍由明确身份的审阅者负责。

清单的 `regions` 指向冻结原生区域；`visual-regions.json` 只是未审目录。对空文本图像不能要求执行者伪造文字引文。逐项核对图义是否进入准确的对象字段，候选对象是否保留相应区域，以及图注和图内信息是否被混淆。文字引文和区域定位均正确仍可能遗漏图义，不能仅凭区域存在给语义 `pass`。
